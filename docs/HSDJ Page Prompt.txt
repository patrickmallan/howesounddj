PRIMARY OBJECTIVE

Make this individual page as fast, efficient, stable, responsive, accessible, search-friendly, and technically clean as it can reasonably be without sacrificing its existing visual identity, artwork, personality, interactions, content, or HSDJ brand vision.

SUCCESS STANDARD

The page must be better in measured production behaviour, not merely cleaner in source code or higher in a synthetic score. Preserve deliberate visual richness while eliminating browser work, downloads, markup, and code that do not contribute to the experience. A change is not an optimization if it causes missing content, delayed accessibility, broken navigation, visual degradation, or a less trustworthy experience.

AUDIT THE COMPLETE PAGE

Inspect the page itself and every shared component, stylesheet, asset, font, script, animation, layout, navigation element, and dependency it causes the browser to load.

Investigate:

- Initial page-load weight and critical rendering path.
- Core Web Vitals and their causes: the actual LCP element and discovery timing, layout-shift sources, and interaction responsiveness rather than scores alone.
- The direct-entry document, embedded RSC payload, route-specific client bundles, shared bundles, CSS, fonts, images, and third-party requests.
- Mobile and desktop resource delivery.
- Images loaded too early, at the wrong size, or at unnecessarily high quality.
- Incorrect preload, priority, fetch-priority, prefetch, lazy-loading, or responsive-image settings.
- Unrelated routes or assets being downloaded before they are needed.
- Production-only Next.js route prefetching triggered by initially visible links, hidden navigation, opening menus, scrolling through card grids, or reaching the footer.
- Oversized images, duplicate artwork, unused formats, and wasteful background images.
- Excessive HTML, DOM nodes, SVG elements, or repeated markup.
- Large server-rendered HTML or RSC payloads caused by repeated SVG identifiers, data attributes, duplicated semantic content, serialized props, or decorative markup.
- Unnecessary client components, hydration, browser-side JavaScript, effects, observers, state, or event listeners.
- Work that can safely remain on the server.
- Animations that continue running off-screen.
- Expensive filters, shadows, blending, compositing, clipping, layout recalculation, or paint work.
- Unnecessary `will-change`, forced GPU layers, timers, loops, or recurring browser tasks.
- Hidden elements that still consume resources.
- Performance techniques such as `content-visibility`, containment, virtualization, or clipping that make meaningful off-screen content disappear from the accessibility tree, find-in-page, printing, screenshots, or crawlers.
- Duplicate CSS, overridden rules, global styles fighting page-specific styles, and unused page code.
- Layout shifts, horizontal overflow, clipped or truncated text, broken wrapping, and undersized tap targets.
- Problems at narrow mobile widths, ordinary phones, tablets, laptops, and large desktop screens.
- Broken links, controls, disclosures, forms, interactions, and keyboard behavior.
- Console errors, hydration warnings, failed requests, and malformed HTML.
- Accessibility issues affecting headings, landmarks, labels, contrast, focus, keyboard use, reduced motion, and semantic structure.
- Whether all meaningful content is available to assistive technology before a sighted user manually scrolls it into view.
- Technical SEO issues involving metadata, canonical URLs, heading hierarchy, crawlable links, structured content, image alternatives, and meaningful page copy.
- Duplicate or unnecessary dependencies and code paths.
- Existing tests that are weak, stale, missing, or failing.

BASELINE AND MEASUREMENT METHOD

- Confirm and record the starting Git branch, commit, and worktree status before editing. Do not absorb or overwrite unrelated user work.
- Record any pre-existing build, lint, type, test, console, or network failures so they are not misreported as regressions or silently folded into unrelated work.
- Build and serve the existing page in production mode before changing it whenever practical.
- Use fresh browser contexts or cold caches for comparable mobile and desktop measurements.
- Measure a direct page entry, a natural full-page scroll, and important interaction states separately. Do not treat “load complete at the top” as the whole page cost.
- Record the actual URLs requested so aggregate byte totals cannot hide unwanted route prefetches or duplicate assets.
- Include the navigation document in page-weight measurements. The Resource Timing resource list does not include the main document, so inspect the navigation entry and/or built HTML separately.
- Distinguish raw built size, compressed or transferred bytes, decoded bytes, request count, and DOM size. Label each measurement clearly rather than combining unlike values.
- Inspect built HTML, RSC files, route chunks, and CSS output when generated markup or client/server boundaries may be a bottleneck.
- Measure layout shift, long tasks, and scroll-frame behaviour where supported. Record the test environment and avoid presenting localhost timing as universal real-user performance.
- Compare like with like. Use the same viewport, cache state, production build, scroll path, and wait conditions before and after.

- Measure initial and post-scroll delivered resources and scrolling/rendering performance on mobile and desktop.

- Check for console errors, failed requests, and hydration warnings.
- Visually inspect the finished page in production mode through normal scrolling as well as screenshots. If an optimization causes blank regions in a full-page capture, printing, the accessibility tree, or find-in-page, investigate rather than dismissing it as a tooling quirk.

- Compare meaningful before-and-after measurements whenever possible.
- Add reasonable, non-flaky performance budgets or regression protection when doing so will prevent the same problem from returning. Prefer budgets for unwanted route requests, request counts, layout shift, long-task duration, overflow, and markup regressions over brittle millisecond-only thresholds.
