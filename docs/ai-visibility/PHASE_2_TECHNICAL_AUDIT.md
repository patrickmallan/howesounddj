## Findings and smallest safe actions

### P1 — Discovered venue/story pages have not been crawled

**Evidence:** GSC Page indexing → “Discovered - currently not indexed” shows 12 affected URLs, last update 2026-10-08, all with `Last crawled: N/A`. The examples are one story (`/stories/what-a-sea-to-sky-gondola-dance-floor-feels-like`) plus 11 venue pages: `brackendale-art-gallery`, `cheakamus-centre`, `cheekye-ranch`, `evans-lake`, `glacier-valley-farm`, `house-of-lager-brewing-company`, `railway-museum-of-british-columbia`, `sea-to-sky-gondola`, `sitka-farms`, `squamish-valley-golf-club`, and `sunwolf`. GSC labels the source “Google systems.” [Google's definition](https://support.google.com/webmasters/answer/7440203#discovered__unclear_status) is that Google knows the URLs but has not crawled them yet; the report's empty last-crawl field is consistent with that. The report shows a historic “Validation passed” entry from 2022, which is not proof that these current URLs were crawled. Read-only URL Inspection of `/venues/brackendale-art-gallery` confirms **not on Google**, discovered via `/sitemap.xml` and referring page `/venues`, with no last crawl. Its **live test at 18:06 PDT on 2026-10-13** returned “URL is available to Google”: Google Inspection Tool smartphone, crawl allowed **Yes**, fetch **Successful**, indexing allowed **Yes**, self-declared canonical, one valid breadcrumb. Thus this representative URL is currently fetchable/indexable in a live test; no live access defect is established.

**Additional comparator check, 18:26 PDT on 2026-10-13:** URL Inspection for the affected Gondola story likewise showed **discovered but not crawled**, sitemap referral, and no last crawl. Its live smartphone test returned **available to Google**, crawl allowed **Yes**, fetch **Successful**, indexing allowed **Yes**, self-declared canonical and one valid breadcrumb. In contrast, `/venues/howe-sound-brewing` is **indexed**: Googlebot smartphone last crawled it **2026-08-25**, fetched successfully with crawl/index allowed and Google-selected canonical equal to the inspected URL. GSC's indexed-venue detail showed “Temporary processing error” under its sitemap field while still showing `/venues` as a referring page; do not extrapolate that field into a sitewide sitemap outage, because the Sitemaps report is currently Success. Both venue detail URLs use the same dynamic page template and self-canonical metadata in source; the Gondola story has a separate self-canonical route and links from `/stories`, the Gondola venue page, and other story pages. This comparison supports a crawl-queue/content-priority investigation, **not** a verified block or a confirmed cause for Google's selection.

**Source content/link review, 2026-10-13:** `src/app/venues/page.tsx` links every active venue from the `/venues` hub, and `src/app/venues/[slug]/page.tsx` presents the same setting/sound/local structure for each. This is a reason to review whether each page gives a couple genuinely distinct planning help and verified venue facts, **not** evidence that Google withheld a crawl because of its copy. Do not manufacture firsthand venue experience or mass-rewrite the template to chase index coverage.

**Business effect:** These local venue pages currently cannot serve as indexed Google results. No evidence yet establishes that the venue pages are the best commercial landing pages or that this status caused the observed AI answer pattern. **Smallest action:** prioritize the genuinely useful venue/story URLs, inspect their distinct content and internal-link prominence, and monitor whether Google crawls them; only make a content/link change if it improves user usefulness or a concrete defect is found. Do not bulk-request indexing, change `robots.txt`, or call a source-system status a website error. **Effort:** small audit; implementation only if a cause emerges. **Risk:** low for inspection, medium for broad changes to venue templates. **Validation:** specific GSC URL Inspection states, live tests, and a later GSC status check. Google's [Page indexing guidance](https://support.google.com/webmasters/answer/7440203) says to prioritize important canonical pages, not 100% index coverage.

## Non-issues / constraints

- GSC lists 4 “Page with redirect” URLs. A redirect URL is normally non-indexed; this count alone is not a defect. Inspect exact targets only if a commercially important URL is affected. [Google's redirect explanation](https://support.google.com/webmasters/answer/7440203#zippy=%2Cpage-with-redirect).
- A sitemap file itself is not a normal content page and need not appear as “indexed.” The relevant signal is the Sitemaps report's successful read, not URL Inspection's “URL unknown” for the XML resource.
- The first-pass AI answers prove neither that HSDJ must publish numeric prices nor that a schema addition would change AI citations. No FAQ, rating, price, or LocalBusiness schema change is justified by the evidence gathered so far.
- Sitewide Organization `areaServed` is Squamish in `src/lib/json-ld.ts`. Patrick has now confirmed Whistler/Pemberton bookings, but structured-data expansion is **not** an urgent or proven AI-visibility remedy. Reconcile visible service copy first and review whether structured data accurately describes the actual business footprint; do not change it in isolation.
